## 1. 构建系统概览

本项目是一个基于 .NET SDK 的源码级代码生成框架，采用 **MSBuild + dotnet CLI** 作为核心构建系统，通过 GitHub Actions 实现 CI/CD。整个仓库以 `src/AutoCode.sln` 为解决方案入口，包含 20+ 个 C# 项目（Source Generator、Analyzer、CLI、示例应用等），并通过 NuGet 包形式对外分发。

## 2. 关键文件与职责

- **`src/AutoCode.sln`**：解决方案文件，定义全部项目的依赖关系与多配置（Debug/Release/Publish）× 多平台（Any CPU/x64/x86）矩阵。
- **`src/AutoCode.Extensions.SourceGenerator/AutoCode.SourceGenerator.Extensions.csproj`**：统一 NuGet 包项目（PackageId=`AM.AutoCode`，当前版本 `2.3.0`），通过 `<DevelopmentDependency>true</DevelopmentDependency>` 标记为开发依赖，不传递到运行时。
- **`.github/workflows/ci.yml`**：GitHub Actions 流水线，定义三阶段任务：`build-and-test`（PR/main 触发）、`pack`（仅 `v*` tag 触发）、`publish`（仅 `v*` tag 触发并推送到 nuget.org）。
- **`scripts/install-autocode.ps1`**：用户侧一键安装脚本，自动执行 `dotnet add package AM.AutoCode --prerelease`、初始化根目录 `autocode.json`、可选创建示例实体。
- **`templates/autocode-webapi/.template.config/template.json`**：`dotnet new` 模板元数据，提供 `autocode-webapi` 短名模板，支持 `enableCrud`/`enableIntercept`/`enableValidation` 参数化。
- **`autocode.json`**：框架自身的全局配置入口（conventions/mapper/dto/webapi/validation/dependencyInjection/cascade/logging/intercept/plugins/customGenerators），也是被安装脚本生成的目标格式。

## 3. 架构与约定

### 3.1 构建流程

CI 流水线固定使用 **.NET 8.0.x**（`actions/setup-dotnet@v4` with `dotnet-version: 8.0.x`），步骤顺序为：
1. `dotnet restore src/AutoCode.sln`
2. `dotnet build src/AutoCode.sln --no-restore --configuration Release`
3. `dotnet test src/AutoCode.sln --no-build --configuration Release --verbosity normal`

### 3.2 NuGet 打包策略

NuGet 包由 `AutoCode.SourceGenerator.Extensions.csproj` 在 **Publish 配置**下通过 MSBuild Target 自动产出：
- `PreBuild` Target：调用 `dotnet publish` 将 `AutoCode.Generators`、`AutoCode.Analyzers`、`AutoCode.DotTemplate.SourceGenerator`、`AutoCode.Model` 分别发布到 `NugetPackage/analyzers/dotnet/cs` 和 `NugetPackage/lib/netstandard2.1`，确保分析器加载上下文能找到依赖程序集。
- `PostBuild` Target：执行 `dotnet pack ... -c Publish -o $(SolutionDir).nuget\`，输出到 `src/.nuget/*.nupkg`。
- 产物通过 `actions/upload-artifact@v4` 上传，再由 `publish` job 用 `dotnet nuget push` 推送至 nuget.org，API Key 来自 `secrets.NUGET_API_KEY`。

### 3.3 版本管理

- 版本号硬编码在 `AutoCode.SourceGenerator.Extensions.csproj` 的 `<Version>2.3.0</Version>`。
- 发布分支策略：**仅当 Git tag 匹配 `refs/tags/v*`** 时才触发 `pack` 和 `publish` 任务；push PR 或 main 分支只执行 build-and-test。
- 未找到集中式版本文件（如 `Directory.Build.props` 或 `global.json`），版本分散在各 csproj 中（例如 `AutoCode.Cli` 单独声明 `<Version>2.0.0</Version>`）。

### 3.4 模板与安装

- 提供 `dotnet new` 模板 `AM.AutoCode.Templates.WebApi`（短名 `autocode-webapi`），位于 `templates/autocode-webapi/`，通过 `.template.config/template.json` 注册。
- 用户可通过 PowerShell 脚本 `scripts/install-autocode.ps1` 一键安装：检测 `.csproj` → 尝试 `dotnet add package AM.AutoCode --prerelease` → 回退为项目引用 → 生成 `autocode.json` → 可选生成示例实体 → 环境诊断。

### 3.5 代码生成产物位置

根据安装脚本提示，编译后生成的代码位于 `obj/Debug/*/generated/` 目录，这是 Roslyn Source Generator 的标准输出路径。

## 4. 约定与约束

- **构建工具链**：所有构建均通过 `dotnet` CLI，无 Makefile、Dockerfile 或自定义 shell 脚本；CI 运行在 `ubuntu-latest`。
- **目标框架**：生成器与分析器统一使用 `netstandard2.1`（见 `AutoCode.SourceGenerator.Extensions.csproj`），保证兼容 .NET Framework 4.7.2+ 及 .NET Core/5+/8+。
- **语言版本**：核心项目显式声明 `<LangVersion>12.0</LangVersion>`（Engine、Generators、Model、Analyzers）。
- **可空引用**：启用 `<Nullable>enable</Nullable>`。
- **配置驱动**：框架行为完全由根目录 `autocode.json` 控制，安装脚本会按默认值生成该文件。
- **发布条件**：只有打 `v*` tag 才会进入打包与发布流程，防止误发。
- **NuGet 包结构**：通过 `<None Include="..." PackagePath="...">` 将 analyzers、lib、tools、Icon 等分目录打入 nupkg，符合 VS 扩展/Source Generator 的规范布局。
- **测试覆盖**：CI 对 `AutoCode.Tests` 与 `AutoCode.Tests.V2` 同时执行，使用 `coverlet.collector` 收集覆盖率。
- **跨平台**：解决方案定义了 Any CPU / x64 / x86 三种平台，但 CI 仅在 Linux 上构建；x86/x64 主要用于本地 Visual Studio 调试。

## 5. 缺失项说明

仓库中不存在 Dockerfile、Makefile、Cake/Fake/GitHub Actions 之外的 CI 文件、以及集中式的 `Directory.Build.props`/`global.json` 版本管理文件；版本与依赖由各 `.csproj` 自行维护。
