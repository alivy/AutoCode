## 1. 使用的系统/方法

本仓库是一个 .NET 解决方案（`src/AutoCode.sln`），采用 **NuGet + `PackageReference`** 作为唯一的第三方依赖管理方式，没有使用 `packages.config`、`global.json`、`Directory.Packages.props`、私有 NuGet 源配置文件（`NuGet.Config`）或 vendoring。所有依赖版本直接内联声明在每个项目的 `.csproj` 文件中。

对于自研产物（AutoCode 框架本身），通过 MSBuild 将项目打包为 NuGet 包（`.nupkg`），由 GitHub Actions 发布到 nuget.org：
- 构建入口：`src/AutoCode.Extensions.SourceGenerator/AutoCode.SourceGenerator.Extensions.csproj`
- 输出位置：`src/.nuget/*.nupkg`（CI 中 `dotnet build ... -c Publish` 后产出）
- 发布流程：`.github/workflows/ci.yml` 在 tag 触发时执行 `dotnet nuget push` 到 `https://api.nuget.org/v3/index.json`，API Key 来自 `secrets.NUGET_API_KEY`。

## 2. 关键文件与包

- **解决方案清单**：`src/AutoCode.sln` —— 仅列出项目路径，不包含任何全局包配置。
- **各子项目 csproj**：每个 `.csproj` 独立声明 `PackageReference`，例如：
  - `AutoCode.Engine` / `AutoCode.Analyzers` / `AutoCode.Generators` 均引用 `Microsoft.CodeAnalysis.CSharp` `4.11.0`、`Microsoft.CodeAnalysis.Analyzers` `3.11.0`。
  - `AutoCode.Benchmarks` 引用 `BenchmarkDotNet` `0.13.12`、`Castle.Core` `5.1.1`、`Microsoft.Extensions.*` `8.0.x`。
  - `APP.WebAPI` 引用 `Swashbuckle.AspNetCore` `6.6.2`、`Microsoft.AspNetCore.Mvc.NewtonsoftJson` `8.0.8`。
- **源码生成器分发包**：`src/AutoCode.Extensions.SourceGenerator/NugetPackage/` 目录包含已打包好的 analyzers DLL（含多语言资源）、`lib/netstandard2.1` 下的运行时库以及 `tools/install.ps1` 安装脚本。
- **CI 流水线**：`.github/workflows/ci.yml` 固定使用 `setup-dotnet@v4` 的 `dotnet-version: 8.0.x`，统一恢复/构建/测试/打包/发布。
- **本地缓存**：`src/.nuget/AM.AutoCode.1.2.0.nupkg` 是手动放入的旧版 nupkg，非当前 CI 产物。

## 3. 架构与约定

- **无集中式版本管理**：没有 `Directory.Build.props`、`Directory.Packages.props`、`global.json` 或 `NuGet.Config`，因此不存在跨项目共享的版本约束；相同包在不同项目中可能声明不同版本（如 `System.Text.Json` 同时出现在 Engine 和 Model 中）。这是当前仓库的实际状态。
- **Source Generator 依赖注入的特殊处理**：`AutoCode.Generators` 和 `AutoCode.Analyzers` 的 csproj 中自定义了 `GetDependencyTargetPaths` Target，把除 `Microsoft.CodeAnalysis.*` 之外的运行依赖 DLL 一并打入 Analyzer 包，避免消费方因缺少依赖程序集而静默失效（注释明确说明 CS8785 FileNotFoundException 问题）。
- **Analyzer 自动注册**：`NugetPackage/tools/install.ps1` 在安装时扫描 `analyzers/dotnet/cs` 等目录，将分析器 DLL 动态添加到目标项目的 `AnalyzerReferences`，使 AutoCode 的分析器/生成器随 NuGet 引用自动生效。
- **CLI 工具**：`AutoCode.Cli` 以 `Version=2.0.0` 独立打包，依赖 `System.CommandLine` 和 `Microsoft.CodeAnalysis.CSharp`，用于命令行驱动代码生成。

## 4. 约定与约束

- **依赖声明位置**：所有第三方依赖均以 `<PackageReference Include="..." Version="x.y.z" />` 形式写在对应项目的 `.csproj` 中；未观察到任何 `GlobalPackageReference` 或中央包管理文件。
- **版本策略**：版本号硬编码在 csproj 中，未使用 `*` 通配符或外部版本文件；同一包在不同项目中的版本基本保持一致（如 `Microsoft.CodeAnalysis.CSharp` 均为 `4.11.0`），但缺乏强制校验机制。
- **PrivateAssets 使用**：编译期仅需要的包（如 Roslyn、Analyzers）普遍标记 `<PrivateAssets>all</PrivateAssets>`，避免传播给消费者。
- **CI 锁定环境**：GitHub Actions 固定 `dotnet-version: 8.0.x`，保证 restore/build/test 行为一致。
- **发布约束**：仅在 `refs/tags/v*` 分支上触发 pack/publish；发布时使用 `secrets.NUGET_API_KEY`，源指向官方 `https://api.nuget.org/v3/index.json`。
- **无私有源/代理**：仓库中未发现 `NuGet.Config`、`NUGET_CREDENTIALS` 或 `GOPRIVATE` 等私有源配置，全部依赖从公共 NuGet.org 拉取。
- **无 lockfile**：未见 `packages.lock.json` 或 `*.lock` 文件提交到仓库，依赖解析结果不纳入版本控制。
