## 构建系统与工具链

该项目采用标准的 .NET SDK 构建体系，以 `src/AutoCode.sln` 为解决方案入口，使用 MSBuild 和 dotnet CLI 进行编译、测试与打包。CI/CD 流程通过 GitHub Actions 自动化执行。

### 核心构建配置

- **解决方案文件**: `src/AutoCode.sln` 定义了 20+ 个项目，涵盖 Source Generator、Analyzer、示例应用、测试等模块
- **目标框架**: 主要使用 `netstandard2.1`（Source Generator）和 `net8.0`（运行时应用）
- **平台支持**: Debug/Release/Publish 三种配置，支持 Any CPU/x64/x86 多架构
- **NuGet 包管理**: 通过 `<PackageReference>` 引入依赖，版本由 NuGet 自动解析

### CI/CD 流水线 (GitHub Actions)

`.github/workflows/ci.yml` 定义了完整的三阶段流水线：

1. **build-and-test**: 在 Ubuntu 上安装 .NET 8.0.x，执行 restore → build → test
2. **pack**: 仅在 `v*` 标签触发时执行，构建 NuGet 包并上传为 artifact
3. **publish**: 下载 artifact 后通过 `dotnet nuget push` 发布到 NuGet.org

### NuGet 包发布机制

`AutoCode.SourceGenerator.Extensions.csproj` 实现了复杂的包构建逻辑：

- **Publish 配置特殊处理**: 当 Configuration=Publish 时，PreBuild 目标会调用 `dotnet publish` 将各个 Source Generator 项目输出到 `NugetPackage/analyzers/dotnet/cs/`
- **包结构**: 遵循 NuGet Analyzer 规范，将分析器放在 `analyzers/dotnet/cs/`，库文件放在 `lib/netstandard2.1/`
- **安装脚本**: `tools/install.ps1` 和 `uninstall.ps1` 自动向项目添加 Analyzer 引用
- **开发依赖标记**: `<DevelopmentDependency>true</DevelopmentDependency>` 确保包不会传递到运行时依赖

### 项目组织模式

- **Source Generator 分离**: 每个代码生成功能独立成项目（AutoCode.Map、AutoCode.Dto、AutoCode.Validation 等），便于单独测试和发布
- **Model 层共享**: `AutoCode.Model` 定义所有属性约定，被各 Generator 共享引用
- **示例应用**: `APP`、`APP.WebAPI` 等作为实际使用示例，验证 Generator 功能
- **测试隔离**: `AutoCode.Tests` 包含单元测试，针对各 Generator 的功能进行测试

### 构建约束与约定

- **增量构建**: 利用 MSBuild 增量编译特性，仅重新编译变更的项目
- **无全局状态**: 每个项目独立构建，不依赖外部构建工具
- **版本管理**: 版本号直接写在 csproj 文件中，通过 Git tag (`v*`) 触发发布
- **跨平台兼容**: 使用 .NET SDK 标准命令，可在 Windows/Linux/macOS 上统一构建
