该仓库是一个基于 Roslyn Source Generator 的 C# 代码生成框架，其错误处理体系主要围绕两个层面构建：**编译期诊断（Diagnostics）**和**运行期异常（Exceptions）**。

## 1. 编译期诊断系统

### 统一诊断收集器
- `AutoCode.Engine/Diagnostics/DiagnosticCollector.cs` 定义了完整的诊断基础设施：
  - `IDiagnosticCollector` 接口提供 `ReportError`、`ReportWarning`、`ReportInfo`、`ReportSuggestion` 四种报告方法
  - `DiagnosticEntry` 结构体封装诊断信息（ID、消息、严重级别、位置、修复建议）
  - `DiagnosticIds` 静态类维护统一的 ID 分配体系（AC1xxx 引擎、AC2xxx Mapper、AC3xxx WebApi 等）
  - `DiagnosticSeverityLevel` 枚举定义 Info/Suggestion/Warning/Error 四级严重性

### Analyzer 诊断描述符
- `AutoCode.Analyzers/Diagnostics/AutoCodeDiagnosticDescriptors.cs` 集中定义所有分析器规则：
  - AC001: 类实现了接口但缺少 [AutoInterface] 特性
  - AC002: 接口与实现类成员不一致
  - AC003: [AutoIgnore] 标记在非公共成员上
  - AC004: 分层违规 - Controller 直接引用数据层类型
  - AC006: 命名规范不符合约定

### 映射器诊断
- `AutoCode.Map/Diagnostics/DiagnosticDescriptors.cs` 定义 Mapperly 相关的诊断（RMG002、RMG008、RMG046），用于语言版本检查、构造函数查找失败等场景。

## 2. 运行期异常处理

### 示例应用中的异常模式
- `APP.WebAPI/Services/UserService.cs` 展示了典型的业务异常处理：
  - 验证失败时抛出 `ArgumentException`，并拼接错误信息
  - 使用 try-catch-finally 块（通过 CodeBuilder 生成）

### 代码生成器的异常支持
- `AutoCode.Engine/CodeBuilder/MethodBuilder.cs` 提供 `Throw()`、`Try()`、`Catch()`、`Finally()` 等方法，用于在生成的代码中插入异常处理逻辑。

## 3. 架构设计决策

### 分层诊断策略
- 编译期错误通过 Roslyn Diagnostic 机制报告，不会中断编译流程
- 运行时错误通过标准 .NET 异常机制处理
- 诊断 ID 按模块前缀组织，便于分类管理和定位

### 无全局异常处理中间件
- 项目未实现统一的异常处理中间件或全局异常处理器
- 异常处理分散在各个服务方法中，采用就地处理模式

## 4. 约束与约定

- 诊断 ID 必须遵循 ACxXXX 格式（x 为模块号）
- 所有诊断必须包含可帮助链接（HelpLink）指向文档
- 严重级别严格区分 Error/Warning/Info/Suggestion
- 运行时异常应携带明确的错误信息和上下文
