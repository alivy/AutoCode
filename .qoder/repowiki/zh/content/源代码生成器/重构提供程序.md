## 简介
本文件围绕"重构提供程序"这一目标，聚焦 AutoCode 工程中的依赖注入与代码生成能力，梳理从源码到运行时的装配流程、生命周期约定、以及通过插件化扩展点实现的重构与自动化能力。**最新更新**：AutoCodeRefactoringProvider已完全重构以支持新的配方系统，现在可以动态发现并显示自定义配方，支持工作区范围的配置共享。**新增功能**：类级别批量 Handler 生成功能，当在类声明上放置光标时，可一键为所有公共方法生成拦截处理器，包括自动添加 [AutoIntercept] 属性和完整的处理器类骨架。

### **新增：类级别批量 Handler 生成功能**

**更新** GenerateHandlerRefactoring 新增了类级别的批量 Handler 生成功能，现在可以在类声明上放置光标时，一键为所有公共方法生成拦截处理器。

#### 类级别批量生成机制
- **触发条件**：当光标位于类声明上且不在任何 public 方法内时，提供批量生成功能
- **智能检测**：自动识别类中的所有 public 实例方法，排除构造方法和静态工具方法
- **批量处理**：为每个 public 方法自动生成对应的 Handler 类，并添加必要的特性标记
- **属性自动添加**：自动为每个方法添加 [AutoIntercept] 和 [CustomIntercept(typeof(HandlerName))] 特性

#### 生成的处理器类结构
- **同步处理器**：继承 MethodHandlerBase<TArgs, TResult>，实现 OnBefore、OnAfter、OnException 方法
- **异步处理器**：继承 AsyncMethodHandlerBase<TArgs, TResult>，实现 OnBeforeAsync、OnAfterAsync、OnExceptionAsync 方法
- **强类型参数**：利用编译时生成的 TArgs 类型，提供完整的 IntelliSense 支持
- **上下文信息**：通过 MethodContext 提供执行上下文，包括耗时、重试次数等信息

```mermaid

```

#### 批量生成工作流程
1. **方法收集**：扫描类中的所有 public 方法，过滤掉构造方法和静态方法
2. **Handler 生成**：为每个方法生成对应的 Handler 类代码
3. **特性添加**：为每个方法添加 [AutoIntercept(Log | Metrics)] 和 [CustomIntercept(typeof(HandlerName))] 特性
4. **代码整合**：将所有生成的 Handler 类追加到当前命名空间中
5. **Using 语句**：确保包含必要的 using 语句（AutoCode.Model）

#### 与传统方式对比
- **传统方式**：需要逐个方法手动添加特性和生成 Handler
- **新方式**：一次操作即可为整个类的所有 public 方法生成完整的拦截处理
- **效率提升**：大幅减少重复性代码编写工作，提高开发效率

### **新增：统一配方系统架构**

**更新** AutoCodeRefactoringProvider已完全重构以支持新的配方系统，现在可以动态发现并显示自定义配方。

#### 配方接口设计
- ICodeGenRecipe：统一的代码生成配方接口，内置生成器和自定义配方都实现此接口
- ClassAnalysisInfo：类分析信息，包含类的元数据和推断标志
- 支持11个内置生成器：AutoEntity、AutoDTO、AutoCrud、AutoValidator、AutoInterface、AutoController、AutoLog、AutoTest、AutoIntercept、MapFrom、Scoped

#### 自定义配方支持
- CodeGenRecipe：声明式定义代码生成规则
- RecipeTrigger：触发条件配置，支持类名模式、属性、方法、接口匹配
- RecipeOutput：输出配置，支持模板、文件名、命名空间占位符
- CustomRecipeAdapter：将JSON配置转换为ICodeGenRecipe接口实现

#### 配置文件加载机制
- RecipeConfigLoader：从autocode.json解析customGenerators配置
- 支持工作区范围配置共享，自动向上搜索autocode.json文件
- 支持JSON注释和尾随逗号，提升配置体验

## 性能考虑
- 增量生成：利用 Engine 的增量特性减少重复编译与生成时间
- 按需启用插件：仅在需要时启用对应插件，降低扫描与生成开销
- 生命周期选择：合理选择 Transient/Scoped/Singleton，避免过度共享状态或频繁创建对象
- 控制器瘦身：将重逻辑下沉至服务层，提升请求处理效率
- **新增**：配方系统缓存：配置文件只在首次访问时加载，避免重复IO操作
- **新增**：批量生成优化：一次性处理所有方法，减少多次语法树操作开销

## 故障排查指南
- 服务未找到
  - 检查是否调用了统一的 DI 扩展方法进行注册
  - 确认服务实现了正确的生命周期标记接口
- 循环依赖
  - 检查服务间是否存在循环引用，必要时引入抽象或重构依赖方向
- 生命周期误用
  - 确保 Scoped 服务不持有 Singleton 状态的长生命周期引用
- 生成失败
  - 查看 Engine 与插件的诊断输出，修正模型或配置错误
- **新增**：配方相关问题
  - 检查autocode.json文件格式是否正确
  - 确认自定义配方的触发条件配置是否准确
  - 验证配置文件路径是否正确，确保能被向上搜索找到
- **新增**：批量生成问题
  - 确认类中存在 public 方法
  - 检查方法签名是否有效（非静态、非构造方法）
  - 验证生成的 Handler 类是否正确添加到命名空间

## 结论
通过清晰的依赖注入约定与插件化的源码生成体系，AutoCode 为"重构提供程序"提供了稳定、可扩展的基础设施。**最新改进**：统一的配方系统进一步增强了系统的灵活性和可扩展性，开发者可以通过简单的JSON配置快速添加自定义代码生成规则，无需修改核心代码。**新增功能**：类级别批量 Handler 生成功能大幅提升了开发效率，开发者只需在类声明上放置光标，即可一键为所有公共方法生成完整的拦截处理器，包括自动添加必要的特性标记和处理器类骨架。建议在新增功能时优先遵循现有约定，借助 Engine 与插件机制实现最小侵入式的自动化与重构能力。
